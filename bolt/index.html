Bolt

Photo viewer for macOS. Open one photo from Finder and go through the whole folder, one key per decision.

Status
Not released. The build is signed ad hoc.
Runs on
macOS 14 or newer
Written in
Swift 6 and AppKit, the system decoder (ImageIO), no third-party dependencies
Tests
82 unit tests of the core, 19 smoke checks that press keys in the built app
License
MIT

I wanted to open a photo from Finder and go through the whole folder with the keyboard, as in IrfanView on Windows. In Bolt Delete sends the photo to the Trash and the next one is already on screen, and keys 1 to 9 move it to folders. Preview can’t flip through a folder, and the viewers that can either lack the system HEIC decoder or are sold by subscription.

On 2 November 2026 I wrote a spec with five scenarios and speed targets. One of them: 400 photos from an iPhone, the best to a folder, junk to the Trash, one key per decision. The spec had a rule that a feature without a scenario doesn’t get in. That night I sent it to Claude Code: “Task for the night: build me a viewer from this spec… Make the interface NOT neural-slop (try hard)… Work autonomously, I’m going to sleep.”

Measured against the spec

Target from the specMeasured
Cold start to first frameunder 250 ms195 to 235 ms
Next photo, median / p95under 16 / 50 ms5.6 / 6.4 ms
HEIC to JPEG1000 photos under 60 s400 photos in 9 s
Memory when idleunder 150 MB104 MB

Measured on a MacBook with Apple M5 and 16 GB, on synthetic 12-megapixel HEIC files with every frame already decoded; the chart above is a separate run on my own photos. I haven’t checked it on an M1 with 8 GB. The cold start is the first thing to check there, because about 100 ms of it goes to starting the HEVC decoder.

No operation deletes a file past the Trash or overwrites an existing one, and ⌘Z undoes every file action. Rotation changes only the Orientation tag; a test checks that the pixels stay byte for byte. The core has 82 unit tests, and 19 smoke checks drive the built app with real key presses.

Keys

← →previous, next photo
Deleteto the Trash, and the next photo is already on screen
1 to 9move to an assigned folder; with ⌥ copy
P X Upick, reject, clear the flag (kept in Finder tags)
Kcompare 2 to 4 photos with one zoom
Gthumbnail grid
⌘Zundo the last file operation
?all keys

Not done yet

  • Notarization and updates: they need a Developer ID, and the build is signed ad hoc.
  • WebP export: ImageIO reads WebP but doesn’t write it.
  • A GPS mini-map: the spec allows the network only for updates, so there are coordinates and an “Open in Maps” button instead.
  • Finding duplicates and bursts.
